## 1. 結論

トップページのヒーローを「小さな庭」から、ロード画面と地続きの「星降るもちスラの庭」へ品質向上する。

ロード中は短いミニゲーム「星雫あつめ」を表示する。集めた星雫をヒーローへ持ち越し、5体のもちスラから1体がランダムなゲストとして現れる。ゲームは待ち時間を隠すためだけの強制演出にせず、ページ準備完了後はいつでも抜けられ、ヒーローから再挑戦できるようにする。

重要な方針は以下。

- 既存のオレンジフードPet、鉢植え育成、昼夜切替は残す
- 5体を常時並べず、ゲストは同時に1体だけ出す
- 5体分、合計約15.8MBのv2スプライトを初回に一括ロードしない
- ロード画面は実ロード状態と連動させ、見せかけの長い待機を作らない
- 大型ライブラリ、ゲームエンジン、React/Vite等を追加しない
- `assets/site-motion.js` へ機能を詰め込まず、新しい責務は別ファイルへ分ける

## 4. 体験コンセプト

### 名称

「星雫を集めて、もちスラの庭をひらく」

### 感情の流れ

1. サイトへ来る
2. 星の門が静かに起動する
3. ロード中に星雫を集める
4. 庭がひらく
5. 集めた色またはセッション乱数に応じて、5体のうち1体が遊びに来る
6. ゲストをタップすると、名前・役割・導線が現れる

占いや診断へ進む前の「誰に会えるだろう」という期待感を作る。派手なカジノ調、連打を煽る演出、診断結果を勝敗化する表現は使わない。

## 5. ロード画面設計

### 表示条件

- HTMLと最小CSSで即表示する
- 700ms未満で準備できた場合はミニゲームを展開せず、短いフェードだけで抜ける
- 700ms以上かかる場合に「星雫あつめ」を開始する
- 重要素材が準備できたら「庭へ入る」を有効化する
- 4秒を超えても重要素材が完了しない場合は、軽量静止画モードで庭へ入れる
- ゲーム完了をページ閲覧の必須条件にしない

### 実ロード進捗

進捗は架空のタイマーではなく、次の状態から計算する。

1. DOM準備
2. 重要CSS適用
3. ヒーロー背景準備
4. ベースPetまたは最初のゲスト用軽量スプライトの`decode()`完了
5. ヒーロー初期化完了

`aria-valuemin`、`aria-valuemax`、`aria-valuenow`を持つ進捗表示を用意する。読み上げは10%刻み程度に抑える。

### 見た目

```text
┌─────────────────────────────┐
│          MOCHISURA          │
│                             │
│      ◌  星の門／発光体  ◌      │
│        もちスラのシルエット       │
│                             │
│   ★       ✦      ★      ✧    │  ← 触れる星雫
│                             │
│      庭をひらいています… 72%     │
│      [━━━━━━━━━━░░░]         │
│                             │
│ [音なし]       [準備後：庭へ入る] │
└─────────────────────────────┘
```

- 深い紺、青紫、青緑の背景
- 金色は達成・導線だけに使う
- 光はぼんやりした面光源にし、細かい点滅を連続させない
- カードUIの金装飾と世界観を合わせる
- ロード画面からヒーローへ、発光体または星雫を共有要素としてクロスフェードする

## 6. ミニゲーム「星雫あつめ」

### ルール

- 画面内をゆっくり漂う星雫をタップ・クリック・キーボードで集める
- 目標は3個。最大プレイ時間は約8秒
- 星雫はDOMの`button`要素で作り、Canvasゲームや物理エンジンを使わない
- 1個取るごとに短い吸い込み、柔らかい発光、数字の更新を行う
- 3個集めると「だれかが庭へ向かっています…」を表示
- 準備完了後はゲーム途中でも庭へ入れる

### 5色とゲスト抽選

星雫には5つの色系統を持たせる。

- 紺・金: 夜空スラ
- 白・金: お金スラ
- 桃・薄紫: 相性スラ
- 紫・青: 毒舌スラ
- 青緑・金: カードスラ

最も多く集めた色を60%の重みで候補にし、残り40%は5体からランダムにする。同数なら完全ランダム。結果は`sessionStorage`へ保存し、同一セッションで毎回変わらないようにする。

### 再プレイ

ロード終了後も、ヒーロー右下に小さな「星雫」ボタンを置く。押すとヒーロー内の軽量オーバーレイで再プレイできる。再プレイしてもページ遷移や診断結果には影響しない。

### アクセシビリティ

- 星雫は順番にTab移動できる
- Enter/Spaceで取得できる
- 取得状況は`aria-live="polite"`で簡潔に通知する
- `prefers-reduced-motion: reduce`では星雫を固定配置し、点滅・軌道移動を停止する
- ゲームをしなくても同じ情報・導線へ到達できる

## 7. ヒーローのギミック設計

### レイヤー

```text
L6  メッセージ／ゲスト詳細／CTA
L5  ランダムゲストもちスラ（同時に1体）
L4  ベースPet・鉢植えPet・星雫
L3  花・草・小さな前景
L2  丘・雲・星座の遠景
L1  昼夜グラデーション
L0  ページ背景
```

大きな半透明パネルをヒーロー全体へ重ねず、コピーと庭をひとつの景色として見せる。現在のCTA「カードを選びに行く」は常に読める位置へ残す。

### ランダムゲスト

- 同時表示は必ず1体
- 初回はロードゲーム結果、ゲーム未実施ならセッション乱数で決定
- 最初のユーザー操作後、2〜4秒で登場
- 入口は小さな星の門、草むら、鉢の陰などキャラに合うものを1つ選ぶ
- 登場時間は約8〜12秒
- 退場後の再登場は45〜90秒の範囲でランダム
- 1セッション最大2回。常時出し続けない
- タップ1回目は情報表示、2回目または明示CTAでリンク先へ進む
- 自動でページ遷移しない

### キャラクター別の小演出

| キャラクター | 登場演出 | タップ時 |
|---|---|---|
| 夜空スラ | 星座線が1本つながる | 小さな月と「十二の景色へ」 |
| お金スラ | 金色の粒が1周だけ回る | コインが1回跳ね「お金の診断へ」 |
| 相性スラ | 2つの光が中央で重なる | ハートが1回脈動「相性を読む」 |
| 毒舌スラ | 紫の稲妻が短く走る | 吹き出し「ズバッと読む？」 |
| カードスラ | カードが1枚だけ浮く | カードが裏返り「一枚引く」 |

全演出は0.4〜0.9秒程度、transformとopacity中心。連続点滅は禁止。

### 既存機能との関係

- ベースPetの歩行とゲスト登場が重なる間は、ベースPetを待機状態にする
- ゲスト登場中は鉢植え操作を止めず、重なり判定だけ避ける
- 昼夜状態は既存`mochisura:sky-mode`イベントを利用する
- ゲストは昼夜に合わせて影と明度だけ変え、別画像を増やさない
- 現行のクリック地点への歩行、なでる、鉢の育成データは壊さない

## 8. 軽量化設計

### ランタイム用素材を別途作る

`pet-runs/`はQA原本。Web実行時に直接5体分を読む構成にしない。

Fableは原本から必要行・必要フレームを抽出し、次のような公開用フォルダを作る設計を提案すること。

```text
assets/hero-pets/
├ manifest.json
├ yozora-idle-walk.webp
├ okane-idle-walk.webp
├ aisho-idle-walk.webp
├ dokuzetsu-idle-walk.webp
└ card-idle-walk.webp
```

目標:

- 1体あたり100〜250KB
- 1セル96〜144px程度で十分
- ヒーローで使う最大20〜24フレームだけを収録
- 透明WebP、必要ならAVIFを追加候補とする
- 原本は変更しない

### 読み込み順

1. HTMLと最小ローダーCSS
2. ヒーロー背景とベースPetの最初の静止フレーム
3. 抽選されたゲスト1体の軽量スプライト
4. ヒーローが表示された後にリンクカード画像
5. 残り4体は`requestIdleCallback`または実際に必要になる直前

### 実装上の性能条件

- 初期クリティカル画像: 合計700KB以下を目標
- 最初の操作可能状態までの転送量: 1.2MB以下を目標
- LCP: 2.5秒以内を目標
- CLS: 0.05以下
- 長時間タスク: 50ms未満
- 常時`requestAnimationFrame`ループは1本へ統合
- `document.visibilityState === 'hidden'`で更新停止
- フレーム更新は30fpsでも自然に見える設計にする
- 画面外セクションは`content-visibility: auto`を検討
- 画像は`new Image()`後に`decode()`し、表示直前のカクつきを避ける
- `will-change`は動いている要素だけへ一時的に付ける
- 5体のフルv2スプライトを`preload`しない

ロード画面は性能問題を隠す免罪符ではない。まず初期転送量を減らし、そのうえで待ち時間を体験へ変換する。

## 9. ファイル分割

新機能を`site-motion.js`へ直接追加し続けない。

推奨:

```text
assets/
├ loading-experience.css
├ loading-experience.js
├ hero-experience.css
├ hero-experience.js
├ hero-pet-runtime.js
└ hero-pets/
```

責務:

- `loading-experience.js`: 重要素材の進捗、ロード画面、星雫ゲーム、退出
- `hero-pet-runtime.js`: スプライト定義、フレーム再生、遅延読込
- `hero-experience.js`: ゲスト抽選、登場・退場、既存庭との協調
- CSS2枚: ロード画面とヒーローの外観・レスポンシブ・reduced-motion

グローバル変数は作らず、IIFEまたは小さなES moduleで閉じる。既存の静的配信環境で動くことを優先する。

## 12. 実装時の禁止事項

- 5体のv2原本を全て初期ロードする
- ロード完了後も無意味に数秒待たせる
- ミニゲーム完了を閲覧条件にする
- 音を自動再生する
- 常時点滅、激しい画面揺れ、無限パーティクル
- 新しい大規模フレームワークやゲームライブラリ
- 診断ロジックやカードセレクターの全面改修
- `site-motion.js`へのさらなる巨大な追記
- 既存の育成`localStorage`データの破壊
- タップ一回で予告なく外部・別ページへ遷移
- ローダーでエラーを隠して永久に閉じ込める

## 13. 受け入れ条件

- ページを開くとローダーが即表示され、白画面にならない
- 高速回線ではローダーが瞬時に抜け、ゲームを強制しない
- 低速時は星雫ゲームが操作でき、進捗表示は実ロードと連動する
- ロード失敗時も4秒程度で通常ページへ入れる
- ヒーローでは既存Pet、鉢植え、昼夜切替が動く
- 5体のうちゲストは同時に1体だけ表示される
- ゲスト画像は選出後に遅延ロードされる
- ゲストのCTAは対応する5ページへ正しく遷移する
- スマホでボタンやキャラが重ならず、44px以上の操作領域を持つ
- キーボードだけでゲーム、ゲスト詳細、退出が操作できる
- reduced-motionで移動・点滅が抑制される
- ページ非表示中はアニメーション更新が停止する
- 既存テストが通り、新機能用の状態・リンク・reduced-motionテストが追加される

## 14. 完成イメージ

「ロード画面」「ミニゲーム」「ヒーロー」を別々の派手な企画にしない。星雫が庭へ落ち、1体のもちスラを呼び、そのまま診断の入口へつながる一続きの体験にする。

主役はキャラクターと選択体験。光、星、パーティクルはキャラクターを見せるためだけに使う。
