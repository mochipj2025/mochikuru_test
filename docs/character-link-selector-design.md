# もちスラLab キャラクター型リンクカード 設計書

作成日: 2026-08-13  
対象: トップページ `index.html`  
状態: 設計レビュー用（未実装・未Push）

## 1. 結論

トップページの「診断」と「もちくる」の入口を、5体のキャラクターから選ぶ円卓型セレクターへまとめる。

おすすめの配置は、現在の「もちスラと暮らしながら…」セクション直後。現行の診断カード4枚と、下段の大きな「もちくる」カードをそのまま残すと入口が重複し、ページが長くなるため、完成時は円卓UIへ統合する。アクセシビリティと一覧性を補うため、円卓の直下には小さな通常リンク一覧を残す。

実装は既存の `assets/site.css` と `assets/site-motion.js` へ継ぎ足さず、次の2ファイルへ分離する。

- `assets/character-selector.css`: 円卓、カード、レスポンシブ、reduced-motion
- `assets/character-selector.js`: 5体のデータ、描画、選択状態、ドラッグ・スワイプ・キー操作

大型ライブラリやビルド環境は追加しない。CSS transform と小さなVanilla JSだけで構成する。

## 3. 既存コードの複雑性チェック

### 判定

現状は「動いてはいるが、トップページの演出層はこれ以上1ファイルへ足さない方がよい」状態。診断ロジックは機能単位に分かれており、今回触らなければ安全性は高い。一方、トップ共通CSSとモーションJSは責務が増えている。

### 主な所見

| 箇所 | 状態 | リスク | 方針 |
|---|---|---:|---|
| `assets/site.css` | 1150行。旧スタイル、現在のトップ構成、浮遊追記が同居 | 中 | 円卓のCSSを別ファイルにする |
| `assets/site-motion.js` | 312行。星屑、マウス追従、カード傾き、庭ゲームを担当 | 中 | 円卓の状態管理を別JSにする |
| `.card` | 診断カードに使う汎用名で、銀河CSSからも一括装飾 | 高 | 新UIは `.portal-card` など固有命名にする |
| Pointer処理 | 背景追従と既存カード傾きがすでに動く | 中 | 円卓のdrag中だけ局所処理し、イベント競合を避ける |
| アニメーション | 常時動作する背景・庭・カードが複数ある | 中 | 円卓はtransform/opacityのみ。常時浮遊は最小限 |
| CSSカスケード | `site.css` の基本色を `galaxy.css` が後から上書き | 中 | 既存トークンを参照し、色の再定義を最小化 |
| ビルド/型検査 | なし | 中 | DOMと状態を小さく保ち、Nodeテストを追加 |

### 今回やらないこと

- 診断ロジックのリファクタリング
- `site-motion.js` 全体の分割
- CSS設計の全面刷新
- npm / Vite / React等の導入
- 他ページのデザイン変更

## 8. 3D配置モデル

選択中を0として、各カードの相対位置を `-2, -1, 0, 1, 2` に正規化する。

| slot | translateX | translateZ | rotateY | scale | opacity | z-index |
|---:|---:|---:|---:|---:|---:|---:|
| -2 | -285px | -250px | +24deg | .78 | .62 | 1 |
| -1 | -165px | -115px | +13deg | .90 | .84 | 3 |
| 0 | 0 | 35px | 0 | 1 | 1 | 5 |
| 1 | 165px | -115px | -13deg | .90 | .84 | 3 |
| 2 | 285px | -250px | -24deg | .78 | .62 | 1 |

数値は最初の夜空スラ試作で実画面に合わせて調整する。カード移動は `520ms cubic-bezier(.22,.8,.3,1)` を基準とする。

## 9. 操作設計

状態は `activeIndex` の1つだけを中心に管理する。

```text
左右ボタン / 左右キー / swipe / drag
                 │
                 ▼
       activeIndex を1つ変更
                 │
                 ▼
  5枚の data-slot と説明エリアを更新
```

カード操作:

```text
中央でないカードを選択 → activeIndexをそのカードへ移す
中央カードを選択       → 対象URLへ遷移
CTAを選択               → 対象URLへ遷移
```

- drag/swipeのしきい値: 42px前後
- 1回の操作で必ず1枚だけ進む
- 高速連打中もインデックスだけを更新し、アニメーション完了待ちのキューは持たない
- ホイール操作は採用しない
- drag直後のclickを1回抑止して誤遷移を防ぐ

## 11. アクセシビリティ

- セクションに固有見出しを付ける
- カルーセルへ `role="region"` と `aria-roledescription` を付ける
- 各カードに `aria-posinset` / `aria-setsize="5"`
- 選択中カードに `aria-current="true"`
- 左右キーはフォーカスが円卓内にあるときだけ処理
- Enterは非中央カードなら中央へ、中央カードなら遷移
- フォーカスリングは既存色と十分なコントラストを確保
- 選択変更は短い `aria-live="polite"` で通知
- 通常リンク一覧を常設し、カルーセル操作が難しい場合の代替経路にする
- `prefers-reduced-motion` では浮遊と初回展開を止め、位置変更を150ms以下のフェードへ簡略化

## 12. パフォーマンス方針

- 3Dは `transform` と `opacity` のみ
- ドラッグ中の更新はrequestAnimationFrameで1フレームに1回まで
- CanvasやThree.jsを追加しない
- IntersectionObserverで画面付近に来るまで初回演出を開始しない
- キャラクター画像に `width` / `height` を指定してレイアウトシフトを防ぐ
- 中央画像は通常読み込み、残りは `loading="lazy"` を検討
- 背景と円盤はCSSで描画し、追加画像を増やさない
